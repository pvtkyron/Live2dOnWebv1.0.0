# デプロイガイド

## 公開面

Project Revには2つの公開面があります。

1. 正規の静的リポジトリページ
2. GitHub管理アセットを利用する任意のBlogfa連携

リリース時は分けて扱ってください。静的サイトで安全な変更でもBlogfaのプレースホルダーや起動処理を壊す可能性があります。

## 公開前

```bash
npm install
npm run build:prod
npm run serve
```

最低限確認するもの:

- `/index.html`
- `/shop.html`と全フィルター
- `/journal.html`と記事
- `/about.html`, `/faq.html`, `/404.html`
- 6製品ルート
- Live2Dの読み込み/操作
- 760px付近のモバイルナビゲーション
- モーション低減設定
- 正規URLとメタデータ
- 日本語表示の折り返しと文字化け

## 静的サイトチェックリスト

- ルート深度に応じた相対アセットパスを維持する。
- ルート追加/削除/改名時は`sitemap.xml`を更新する。
- 検索導線変更時は`sitemap.html`も更新する。
- `robots.txt`が正規サイトマップを指すことを確認する。
- `404.html`は`noindex`のままにする。
- HTML/JavaScriptに秘密情報や環境固有認証情報を入れない。

## Live2D変更

`src/`変更で公開バンドルも変わる場合:

1. 本番ビルドを作る。
2. `dist/live2d_bundle.js`の生成/読み込みを確認する。
3. 人が書いたソースと生成差分を区別しやすくする。
4. 参照モデル/テクスチャの存在を確認する。
5. SDKv2/v4両方を維持するなら代表モデルを両方テストする。

圧縮版バンドルが配信経路で使われている間は、`.gz`/`.br`を不用意に削除しないでください。

## Blogfaチェックリスト

- `<-BlogUrl->`などのプレースホルダーを完全に維持する。
- 安全/ネイティブ経路をテストする。
- GitHub/CDN取得失敗をシミュレートする。
- Blogfaネイティブ面が残ることを確認する。
- Live2D失敗が健全なストアを破壊しないことを確認する。
- 新しい外部ホストを追加する場合は必要性を文書化する。

## ロールバック

原因となる最小変更をGitで取り消すのを優先します。正規サイトは静的ファーストなので、対象HTML/CSS/JavaScriptを戻せばデータベース移行なしで以前の挙動へ戻せます。

Blogfa不具合では、まず直近の正常な起動/監視ファイルへ戻します。拡張レイヤーが不健全なままなら、安全/ネイティブ経路を使って表示を維持してください。

## 一緒に混ぜないもの

依存関係がない限り、次の変更は同じリリースに混ぜないでください。

- 編集文と生成済みバンドル
- Blogfa起動処理と無関係なストア装飾
- モデルアセット交換とSEOルート変更
- 依存関係/ツールチェーン更新とビジュアル再設計

変更境界を小さくすると、静的面とBlogfa面の検証とロールバックが簡単になります。
